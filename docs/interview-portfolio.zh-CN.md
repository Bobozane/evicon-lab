# EviCon-Lab：面试展示闭环

这个入口把当前研究路线整理成一个可以现场运行的、完全离线的工程闭环。它的目标是展示实验基础设施如何工作，不把工程 smoke 误写成模型行为结果。

## 一条命令

在仓库根目录运行：

```bash
.venv/bin/python -m evicon.interview_portfolio
```

默认会在 `outputs/interview-portfolio-v1/` 生成四个脱敏文件。只想检查而不写文件时运行：

```bash
.venv/bin/python -m evicon.interview_portfolio --dry-run
```

同一个输出目录需要重新生成时，必须显式使用 `--overwrite`：

```bash
.venv/bin/python -m evicon.interview_portfolio --overwrite
```

这个命令不联网、不读取 API key、不构造真实模型服务，也不执行 12-request 行为资格实验。

## 已实际使用的 Agent 技术栈

这部分可以直接作为面试中的技术栈说明，下面每一项都对应当前仓库里的实现：

- **Python 3.11+**：核心运行时、命令行入口和实验编排；
- **Pydantic 2**：严格数据契约、结构化输出、配置校验和不可变状态对象；
- **自研 Agent 运行时**：统一处理内容渲染、Provider 调用、JSON 解析、字段校验和安全审计；
- **OpenAI 兼容接口适配**：用统一的 Provider 契约连接真实服务，网络边界显式受控；
- **FakeProvider/FakeTransport**：在完全离线环境中模拟合法响应、格式错误、超时和 HTTP 故障；
- **来源图与来源根归并**：识别同源转发、独立来源和公开证据关系；
- **Exposure Ledger 与轮次快照**：记录 Agent 实际看见的内容，限制未暴露内容被使用或传播；
- **多轮传播、控制器和回放验证**：检查时序、可见性、干预应用和结果引用；
- **TOML + JSON/JSONL**：版本化实验配置、脱敏轨迹、运行报告和回执；
- **pytest + SHA-256**：离线契约测试、故障注入和代码/配置/输出完整性绑定。

准确的能力定位是：**Agent 应用运行时和可审计实验基础设施研发**。当前项目不包含大模型训练或微调，也没有把未实际使用的 LangChain、LangGraph 等框架写成依赖。

## 闭环包含什么

```text
固定来源与状态协议
        ↓
离线合成对照检查
        ↓
公开视图上的来源关系规则提案
        ↓
多轮传播与实际暴露记录
        ↓
传播回放、干预应用回放
        ↓
脱敏报告、轨迹和代码指纹
```

离线运行包括：

- 来源条件和解析器的 192 个逻辑请求；
- 初始判断到后续更新的 288 个逻辑请求；
- 4 类场景、4 种条件、48 次确定性传播运行；
- 48/48 条传播回放通过，48/48 条干预应用回放通过；
- 16 个公开控制器规则案例，16 个结构化提案有效；
- 144 个公开暴露事件和 27 个传播运行中的控制器提案。

控制器规则案例会给出一个容易解释的对照：同源重复只对应一个来源根，因此可以提出“请求独立来源”；两个独立来源根不会因为消息数量而被直接打断；带公开支持的少数纠正也会被保留为可审计动作。这里展示的是预先写明的规则输出，不是模型已经学会了这些行为。

## 输出文件

- `portfolio_report.json`：机器可读的运行链路、检查结果、计数和解释边界；
- `portfolio_report.md`：适合面试时打开的中文说明；
- `portfolio_trace.jsonl`：只含阶段、ID、计数、动作、来源根数量和回放状态；当前包含 16 条控制器轨迹和 48 条传播轨迹；
- `portfolio_receipt.json`：绑定输出文件哈希、15 个代码或配置文件哈希（包括本入口自身）、版本和安全状态的回执。

回执中的 `output_sha256` 对报告、说明和轨迹做哈希；回执本身不对自己做哈希，以避免循环依赖。所有输出均不包含提示词、完整模型回复、密钥、请求头、provider metadata 或 evaluator-private truth。

## 面试时可以这样讲

> 我的项目关注的不是消息数量，而是消息背后有多少独立来源。为了让这个问题可测，我把来源图、实际暴露快照、结构化 Agent 输出和回放审计串成了一条链。控制器只能读取公开视图，同一来源被多次转发仍只计一个来源根；每轮结束后还能检查 Agent 实际看到了什么、干预是否在正确轮次生效。现在我先用完全离线的合成模拟验证协议、状态更新和四类网络场景，生成脱敏回执；真实模型行为和论文结论会作为后续单独授权的实验阶段。

## 当前边界

这个闭环可以证明：

- 来源归并、实际暴露记录和轮次回放能够协同工作；
- 前后状态协议和来源条件对照可以被离线验证；
- 控制器提案、干预应用和结果记录具有可审计边界；
- 运行产物可以绑定到代码和配置指纹。

它不能证明：

- LLM 在真实调用中一定会使用来源独立性；
- 某个干预已经降低错误级联或保护了少数意见；
- 存在因果效果、普遍行为规律或论文结论。

旧 H-G、H-D、WVS、002/003、calibration、ledger、receipt 和分析产物仍保持原目录隔离，不与这个面试展示闭环合并统计。
