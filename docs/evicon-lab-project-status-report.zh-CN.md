# EviCon-Lab 项目报告

**报告日期：** 2026-08-29  
**项目名称：** EviCon-Lab  
**拟投稿方向：** 多智能体系统（AAMAS 2027，具体征稿时间以官方通知为准）  
**报告性质：** 工程与研究状态报告，不是论文结果报告

> 本报告的核心结论：EviCon-Lab 已经完成了来源追踪、实际暴露记录、时序回放、结构化 Agent 运行和离线评分等实验基础设施；新的 v3 来源行为资格协议也已经完成设计、离线验证和一次性 Provider 兼容性检查。但是，面向主研究问题的“初始判断 → 社会暴露 → 最终判断”多轮实验尚未完成，因此目前没有行为效果、因果效果或论文结论。

## 1. 项目概述

### 1.1 研究目标

项目研究的是合成、离线的 LLM 多智能体社交网络。每个 Agent 可能会看到其他 Agent 发送的消息，也可能看到带有来源和证据说明的材料。研究要区分两种外表相似、但科学含义不同的行为：

1. Agent 因为获得了新的、可追溯的独立证据而合理更新观点；
2. Agent 只是因为同一条信息被不同 Agent 重复转发，误把重复次数当成了证据数量。

进一步的问题是：如果系统明确显示消息来自同一个来源，或者显示消息来自多个独立来源，是否能够减少错误信息级联，同时不压制有独立证据支持的少数纠正意见？

### 1.2 三类信息的操作性定义

这三类信息不是一个简单的“三选一”变量，而是两个相互独立的维度：

| 维度 | 可能取值 | 含义 |
|---|---|---|
| 社会消息的来源依赖 | 来源未披露、同一来源、多个独立来源 | 描述多条社会消息之间是否有共同上游来源 |
| 新事实材料 | 没有、提供外部证据 | 描述 Agent 是否获得了独立于社会表达的证据卡或原始记录 |

“同源重复”和“独立来源”由来源图确定，不由 Agent 根据文字相似度猜测；“外部证据”必须作为单独的证据对象暴露，不能把另一条 Agent 消息直接称为证据。

### 1.3 研究边界

项目目前只使用作者编写的合成材料和离线审计流程，不读取真实用户社交数据，不使用 WVS 数据作为新路线的行为材料，也不把评估者私有真值暴露给 Agent 或控制器。

项目不试图判断现实世界中哪些政治或价值观点应该获胜，也不把“意见趋同”本身视为错误。只有在没有新增独立支持材料的情况下，错误方向的社会驱动改变，才会被定义为潜在的有害从众。

## 2. 总体系统结构

当前系统可以理解为一台“来源追踪的实验仪器”：

```text
合成主张、消息和证据
          │
          ▼
     来源关系图
          │
          ▼
  实际暴露记录与轮次快照
          │
          ├──────────────┐
          ▼              ▼
   Agent 结构化判断   公开视图控制器
          │              │
          └──────┬───────┘
                 ▼
       下一轮传播与干预应用
                 │
                 ▼
            回放审计
                 │
                 ▼
      离线评估（此处才加载私有真值）
```

一个重要的边界是：模型只看到当时真实暴露给它的公开内容；评估者在实验结束后才把私有真值与公开行为记录连接起来。控制器也不能读取私有真值。

## 3. 已实现的系统能力

### 3.1 来源图与来源根归并

相关实现位于 [来源图模块](/home/ubuntu/evicon-lab/src/evicon/provenance_cascade.py)。当前系统能够：

- 表示主张、证据卡、来源根、消息节点和消息之间的转发或引用关系；
- 检查重复 ID、跨场景关系、跨主张传播、时间倒置和环；
- 沿转发链向上追溯来源根；
- 防止共享上游的消息被错误标记为独立来源；
- 将“来源身份”与“来源是否真实”分开；
- 将评估者的真值标签放在独立的私有文件中。

因此，两个不同 Agent 说了同一句话，并不自动算两个来源。如果二者都追溯到同一个原始报告，系统只计算一个来源根。

### 3.2 实际暴露、轮次快照与传播权限

相关实现位于 [暴露与快照模块](/home/ubuntu/evicon-lab/src/evicon/provenance_cascade_exposure.py)。当前系统能够：

- 以追加方式记录某条内容或证据何时暴露给哪个 Agent；
- 在每轮开始时为每个 Agent 生成不可变的公开视图；
- 只允许 Agent 使用已暴露的内容和证据；
- 阻止未暴露的父消息通过来源关系“凭空”获得传播权限；
- 检查内容和证据是否在当前轮次已经存在；
- 根据公开视图提供可见来源关系，而不是把完整内部图交给 Agent。

这使得实验能够回答“Agent 当时实际看到了什么”，而不是仅凭最终对话文本推测。

### 3.3 回放审计

当前有两类回放检查：

- 暴露回放：检查每个 Agent 的可见内容、来源关系和轮次顺序；
- 结果与干预回放：检查干预是否只能影响下一轮、传播内容是否符合当时快照。

回放审计是系统级有效性条件。若某个运行无法通过回放，就不应进入行为分析。

### 3.4 控制器与干预应用

当前框架支持四类条件：

- 无干预；
- 普通异议或要求重新思考；
- 只看消息数量和公开内容的来源盲控制器；
- 可以读取可见来源关系的来源感知控制器。

干预提案可以请求：

- 独立来源核验；
- 基于证据的重新推理；
- 优先暴露已经预先授权的证据。

提案只能在下一轮生效；控制器发出的指令不是事实、证据或真值。

当前控制器底层机制已经具备识别“多条消息只有一个可见来源根”的能力，也能在看到多个可见来源根时避免简单压制。不过，主实验仍需要一个不读取场景答案、只依赖公开信号的新版策略。旧基础控制器的部分分支会读取预先登记的场景类型，这不适合直接作为最终论文算法。

### 3.5 Agent 运行时与安全边界

当前 Agent 运行时支持：

- 严格的结构化输出契约；
- 只能引用实际可见的内容和证据 ID；
- 解析失败时停止，而不是猜测性修复；
- 有限重试、请求指纹和断点恢复；
- 防止覆盖已有结果；
- 请求账本和安全字段的脱敏处理。

新的 v3 兼容性门进一步限制了 Provider 使用：默认完全离线；只有显式允许网络时才构造 Provider；一次兼容性检查最多一次 HTTP 请求；不保存完整提示词、完整模型回复、密钥、请求头或 Provider 元数据。

### 3.6 离线评估指标

现有离线评估框架预注册了九项指标：

1. 错误级联采纳率；
2. 有支持的纠正意见保留率；
3. 有益信息接受率；
4. 有害从众率；
5. 干预误报率；
6. 来源多样性；
7. 回放审计通过率；
8. Token 成本；
9. 延迟。

私有真值只在离线评分阶段加载，不进入 Agent、控制器、提示词或公开审计产物。

## 4. 当前新路线：来源行为资格协议 v3

### 4.1 v3 的目的

v3 不是主实验，而是先检查模型是否能够理解并使用“来源关系”这一测量因素。它修复了 v2 中决策任务过于空泛、所有场景最终退化成两条重复消息的问题。

### 4.2 v3 的设计

v3 使用四个作者编写的合成场景。每个请求都包含：

- 一个明确的目标主张；
- 一个可逆的具体决策任务；
- 两条文本完全固定的焦点消息；
- 两条固定的反例、限制或记录消息；
- 每条可见消息的公开来源关系。

只改变焦点消息的来源投影：

| 投影 | 焦点消息的公开来源关系 |
|---|---|
| `source_free` | 不显示来源关系 |
| `same_root` | 两条消息显示同一个来源根 |
| `independent_roots` | 两条消息显示两个不同的来源根 |

共有四个场景、三个投影、三个种子，共计划 36 个逻辑请求。投影顺序使用平衡轮换，内部场景 ID、条件名称和预期答案不写入提示词。

模型输出限制为：

- 五级判断；
- 与判断一致的公开行动；
- 是否分享；
- 1 到 7 的信心；
- 使用过的内容 ID；
- 分享的内容 ID。

### 4.3 v3 已完成的验证

## 5. 历史实验及其正确解释

### 5.1 H-G、H-D、WVS 和其他旧批次

这些批次保留在仓库中，主要用于验证：

- Provider 接口和错误处理；
- 请求账本、断点恢复和不覆盖；
- 暴露时序和回放；
- 控制器提案及下一轮应用；
- 解析失败和超时边界。

它们不能与新 v3 或未来主实验合并，也不能作为干预效果或因果效果的证据。旧批次经常出现以下问题：错误采纳的地板效应、可分析单元不足、条件分离不明显、首轮内容时序问题、公开文本与条件可识别性问题，以及输出截断。

### 5.2 v2 来源行为资格批次

v2 的 12 个请求已经完成并完成离线描述性分析。结果是所有有效回复都选择了采纳和分享，四个配对差异为 0。

正确解释是：v2 的测量任务没有把场景主张、纠正材料和具体决策真正放入请求，导致四个场景在行为上不可识别。这是测量设计失败，不是“没有来源效应”，也不是“证明模型一定从众”。

v2 文件和结果继续独立保存，不会被 v3 重写或合并。

## 6. 数据安全与可审计性

当前系统的安全边界包括：

| 项目 | 当前做法 |
|---|---|
| 网络 | 默认关闭；真实调用需显式授权 |
| API 密钥 | 运行时可读取，但不写入结果或收据 |
| 提示词 | 新 v3 兼容性收据不保存完整提示词 |
| 模型回复 | 不保存完整回复，只保留允许的结构化状态 |
| 请求头 | 不保存 |
| Provider 元数据 | 不保存 |
| 私有真值 | 只在离线评分时读取 |
| 历史材料 | 新 v3 不读取旧 Pilot、WVS 或 v2 结果 |
| 结果覆盖 | 已有收据或结果会阻止覆盖 |
| 论文结论 | 协议和收据显式标注“非论文结果、无因果结论” |

需要特别注意：旧真实 Agent 运行器的某些运行事件会保存完整消息，因此不能直接作为新 v3 的脱敏运行器使用。新运行器必须使用独立的安全输出契约。

## 7. 当前科学缺口与风险

### 7.1 还不能区分“合理更新”和“盲目从众”

一次性判断只能回答“模型在当前视图下选择了什么”，不能回答“它是否因为社会暴露而改变”。主实验必须有：

```text
独立初始判断（T0）
        → 社会消息或外部证据暴露
        → 最终判断（T1）
```

只有将 T0 与 T1 配对，才能定义错误方向的社会驱动改变。

### 7.2 v3 的来源披露因素仍与来源独立性混合

`source_free` 不显示来源，而另外两个投影显示来源根。因此 `same_root - source_free` 同时包含“开始显示来源”和“显示同源来源”两个变化。

主实验应增加“来源隐藏/显示 × 潜在同源/独立”的设计，或者把结论限定为“来源披露与独立性敏感性”，不要声称这是纯粹的同源因果效应。

### 7.3 外部证据目前没有独立行为分支

固定的反例或记录文本不等于完整的外部证据实验。主实验应使用预先登记的证据卡，明确记录：证据内容、来源、与主张的支持或反驳关系、引入轮次和可见 Agent。

### 7.4 控制器不能知道场景答案

控制器如果根据 `false_majority` 或 `true_minority_correction` 这样的场景类别决定动作，就可能近似知道答案。最终控制器只能使用公开的：

- 可见消息数量；
- 可见独立来源根数量；
- 公开验证状态；
- 已暴露证据卡及其支持/反驳关系；
- 传播轮次和时序。

场景类别只能用于实验分层和离线评分。

### 7.5 干预必须真正改变可见信息

“请求独立来源”本身不是独立来源。如果下一轮没有预先授权的核验证据可供投递，干预只能改变措辞，无法检验证据感知是否产生效果。

### 7.6 样本和外部有效性仍不足

当前只有一个 Provider、一个模型和一个 36-case 资格设计。正式结论还需要更多种子、至少两个模型和多个网络拓扑，并且要以场景—种子为主要重复单位进行统计。

### 7.7 旧网络运行器不能直接作为主实验

旧运行器的首轮快照和初始内容追加存在时序耦合，通用提示上下文有时只传 ID 而不传可读内容；这些问题可能导致首轮 Agent 实际看到空视图或不可用信息。主实验必须在离线资格检查中验证每个场景确实有初始暴露、社会暴露、纠正暴露和最终结果。

## 8. 建议的主研究设计

### 8.1 第一层：来源依赖识别基准

建议沿用共享初始判断的配对思路，构造以下条件：

1. 私有初始判断；
2. 无 Peer 的自我反思；
3. 不显示来源的文本重复；
4. 显示同一来源根的重复消息；
5. 显示多个独立来源根的消息；
6. 直接暴露外部证据卡。

每个场景和种子先生成同一个 T0，再把相同的 T0 分支到不同条件。这样可以计算：

| 配对差异 | 解释 |
|---|---|
| 自我反思 − 初始判断 | 模型自身的不稳定性 |
| 文本重复 − 自我反思 | 单纯重复文本的影响 |
| 同源重复 − 文本重复 | 来源披露与同源关系的综合增量 |
| 独立来源 − 同源重复 | 在来源已显示时，独立性的增量 |
| 外部证据 − 自我反思 | 新证据的接受增量 |

### 8.2 第二层：多轮社会网络和干预

在第一层可识别后，再把条件接入真正的多 Agent 网络：

- 初始网络：六到八个 Agent；
- 初步实验：三轮；
- 每个 Agent 只使用自己的轮开始快照；
- Agent 的分享决定下一轮实际送达内容；
- 同源和独立来源的消息数量、文本和发送顺序尽量匹配；
- 纠正证据来自预先锁定的公共证据池；
- 控制器只读取当前公开视图。

建议覆盖四类合成场景：

- 错误观点形成多数；
- 正确但少数的纠正意见；
- 多个独立来源支持的正确共识；
- 证据不足、应当保持不确定的争议。

### 8.3 控制器策略

来源感知策略的第一版可以使用公开信息计算：

```text
消息总数 = n
可见独立来源根数 = r
可见支持/反驳证据数 = e
```

例如，在主张尚未验证、消息很多但 `r = 1` 时，下一轮请求独立核验；在已有多个独立来源时不因为“意见不一致”而自动压制；在出现公开反驳证据时请求基于证据重新推理。

这里的规则必须固定、可复现，并且不能读取场景真值。应测试以下不变量：

1. 同源重复不应被当作新增独立证据；
2. 独立来源增加应能改变来源计数；
3. 未暴露的来源不能影响当前 Agent；
4. 干预只能影响下一轮；
5. 有独立证据支持的纠正不应被普通去重策略压制。

### 8.4 评估指标

现有九项指标可以继续使用，但主实验还应增加：

- 同源重复带来的判断增量；
- 独立来源带来的判断增量；
- 错误级联规模和深度；
- 消息数量与独立来源数量的膨胀比；
- 信心变化和校准；
- 证据引用类别；
- 缺失、解析失败和无合格单元比例。

“有害从众”不应定义成所有采纳行为。建议定义为：

> Agent 在没有新增独立支持证据时，因同源社会重复而从相对正确的初始判断转向错误判断，并在后续传播中继续扩大该错误。

“有益接受”则是：

> Agent 因独立证据支持而采纳原本少数但正确的纠正意见。

### 8.5 统计和重复

在小规模开发阶段，可以报告配对差异和描述性区间，但不能把六个 Agent 当成六个独立实验样本。正式阶段应：

- 以场景 × 种子作为主要重复单位；
- 使用配对置换或符号翻转方法，或预注册分层模型；
- 报告置信区间和缺失率；
- 做场景留一验证；
- 至少比较两个模型和多个拓扑；
- 把普通的答案翻转指标与严格来源分解指标并列报告。

## 10. AAMAS 定位与可防守贡献

项目不应声称：

- 第一个发现 LLM 会从众；
- 第一个多 Agent 从众基准；
- 第一个来源隐藏控制；
- 第一个社会干预方法。

这些方向已经有相邻研究。更可防守的定位是：

> 面向 LLM 多智能体社会学习，建立一个可审计的来源依赖评测与干预框架，将相关联的社会报告、独立来源佐证和可验证外部证据正交拆分，并用逐 Agent、逐轮暴露记录和回放验证避免把消息重复误判为证据累积。

要让这个定位成为计算机多智能体论文贡献，必须同时展示：

1. 明确的协议或算法不变量；
2. 可复现的运行器和安全审计；
3. 普通答案翻转或消息计数指标与严格来源分解指标得出不同结论的测量失败实验；
4. 至少一个来源感知策略相对于来源盲基线的可重复比较；
5. 错误级联下降和正确纠正保留之间的代价，而不是只报告“同意变少”。
