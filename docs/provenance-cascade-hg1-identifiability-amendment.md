# H-G.1 Identifiability Amendment

H-G.1 is a versioned, development-only pilot design. It does not overwrite, resume, or merge the H-G real Pilot or its H-F analysis. H-G remains a non-separating engineering pilot.

## Root-cause audit

The historical runner constructed each round-start snapshot before appending `initial_public_content` for that round. Round-zero Agents therefore received no substantive public claim, producing many `no_position` observations and breaking the initial-stance transition chain. The historical controller also branched on the configured scenario type. That shortcut protected independent consensus before the source-blind condition had to reason from its permitted surface signals, reducing the intended information contrast. Finally, the old smoke checked correction eligibility but did not freeze initial substantive, correction-transition, harmful-cascade, and share-decision denominators together.

## Versioned timing

H-G.1 treats declared round-zero public content as a pre-session public exposure. It is recorded in the public ledger and is visible in the immutable round-zero snapshot. Each Agent receives exactly one pre-session message. Agent 03 receives the second surface-matched message and may enable one pre-registered round-zero repost to neighboring Agent 02. That social exposure first appears in Agent 02's round-one snapshot; no Agent observes two messages before its round-zero outcome. Correction or evidence material is delivered after round one and first appears in round two. Proposals are created only after the current-round outcomes; any schedule is effective only in the next round.

## Source-pair design

The false-majority and independent-consensus cases use matched public claim wording, message count, and delivery timing. The paired schedule uses the same actor, target, channel, message count, and round. In the false-majority graph the second message resolves to the same root, so Agent 02 sees two messages but one root. In the independent-consensus graph it resolves to a distinct public root, so Agent 02 sees two messages and two roots. Source-blind and generic controllers receive no root data. The provenance-aware controller may use only root relations in the target Agent's current snapshot. Scenario type remains study metadata and is not used by the H-G.1 decision function.

## Protected boundaries

Evaluator truth remains in a separate private fixture and is loaded only for offline eligibility checks. It never enters Agent prompts, controller views, proposals, directives, ledgers, or public smoke output. Directives remain process requests, not facts or evidence. Supported corrections are never hidden, deleted, or downgraded. Contested disagreement remains eligible for uncertainty and abstention.

## Interpretation

The FakeProvider smoke validates timing, replay, eligibility denominators, and structural decision opportunities. It is not an effectiveness experiment and cannot support a paper or causal conclusion. A real Pilot requires separate researcher approval and a one-shot provider compatibility receipt bound to this exact config and protocol.
