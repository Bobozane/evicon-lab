# 来源依赖观点更新协议（v1 设计稿）

## 状态

这是下一阶段的**设计稿**，不是已执行的实验、不是注册完成的协议，也不授权网络调用。它不读取或重用已完成的 v2 因素分解批次、旧 H-G/H-D/WVS 批次、ledger、receipt、分析结果或 evaluator-private truth。

它的作用是修复已完成开发试跑暴露出的两个构念问题：一是不同条件曾是彼此独立的请求，不能严格称为同一 Agent 的观点更新；二是“重复文本”“来源独立性”和“新增证据”还没有完全拆开。

## 目标

对每个逻辑实验单元，测量一个明确的公共状态转换：

```text
J0：独立初始判断
    -> 仅见 J0 的自我反思
    -> J0 + 未显示来源的社会重复
    -> J0 + 显示为同一根的两条社会报告
    -> J0 + 显示为两个独立根的两条社会报告
    -> J0 + 直接 EvidenceCard
    -> J1：新的公开判断、信心、采纳和分享决定
```

这里“同一 Agent”指同一个逻辑单元、相同模型、相同场景和固定随机种子。LLM 调用本身仍是无状态的；因此 J0 的**结构化公开判断**会作为后续请求的可见材料显式传入。不能把没有传入 J0 的两个独立请求称为观点更新。

J0 和 J1 都只保存允许公开审计的结构字段，例如判断等级、信心、采纳/分享决定和实际引用的可见内容 ID。不保存 prompt、完整回复、推理文本、API key、headers 或 provider metadata。

## 条件与可识别比较

| 条件 | J1 额外可见材料 | 可回答的问题 |
|---|---|---|
| `self_reflection` | 无新社会材料，只有 J0 | 模型本身是否会改变 |
| `source_unshown_repetition` | 两条文字匹配的社会报告，不显示根 | 新增社会文本和消息数量的影响 |
| `same_root_shown` | 同一对社会报告，显示为同一公开根 | 已知同源重复的影响 |
| `independent_roots_shown` | 同一对社会报告，显示为两个公开根 | 独立社会佐证的增量 |
| `direct_evidence` | 一张单独标识的 EvidenceCard | 直接可检查材料的影响 |

对于同一场景、立场方向和消息顺序：`source_unshown_repetition`、`same_root_shown`、`independent_roots_shown` 的两条社会报告文本、目标主张、任务、位置和顺序必须完全相同。它们唯一可见的差别是根是否显示以及显示成一个还是两个根。

不再把“同源但隐藏”和“独立但隐藏”作为两次不同的真实模型调用。它们对 Agent 的公开输入必须字节级相同，因此最多只能被作为同一 `source_unshown_repetition` 请求的两个 evaluator 侧潜在来源标签，用于检查实现不会把不可见来源泄漏进 prompt。把同一个公开 prompt 重复发送两次，再把输出差异解释为隐藏来源效应，是不成立的。

`direct_evidence` 不是“更多社会消息”。它使用可见材料类型 `direct_evidence_card`，并明确说明它是原始记录、测量或可核查条目的摘要；它不携带“这就是真的”标签。EvidenceCard 的字数、肯定程度和任务相关性应在作者盲审阶段与社会报告尽量匹配，但它不需要假装与社会报告是同一类材料。

## 场景和材料的预先约束

第一版拟使用新的公开合成场景，至少覆盖：

1. 支持某一主张的社会报告；
2. 反对某一主张的社会报告；
3. 证据不足、理应保留不确定性的争议；
4. 少数纠正意见带有直接 EvidenceCard 的情形。

每个场景都必须有两条社会报告、可选的一张 EvidenceCard 和一个中性、可逆的决策任务。公开文本不应出现“正确答案”“可信来源”“独立来源更可靠”“多数应当被相信”或类似诱导语。私有真值如用于最终离线评分，只能存放在 evaluator 侧，不能进入 Agent、Controller、prompt、公开审计或收据。

材料作者在查看任何新模型输出前要固定以下项目：

- 两条社会报告的长度、语气、支持强度和具体性；
- 目标主张和反向主张的措辞；
- 根标签的语义表示、根编号置换和消息顺序置换；
- EvidenceCard 的材料类型和可见 ID；
- 每个场景属于“支持、反对、未决、少数纠正”的 evaluator-only 标签；
- 排除、失败停止和主要比较规则。

不能用 v2 的 32 条结果挑选“更容易出现来源效应”的场景，也不能在查看新结果后删除没有差异的场景。

## 请求与状态机

每个组先生成一次 J0。该请求只包含目标主张、任务和固定上下文，没有新的社会报告或 EvidenceCard。J0 的合格输出形成一个最小公共状态：

```text
public_prior_judgment = {
  ordinal_judgment,
  public_action,
  confidence,
  content_ids_used,
  share_decision,
  share_content_id
}
```

随后每个 J1 分支把这份状态作为 `visible_public_prior_judgment` 传入，并仅增加本条件允许的公开材料。后续 Agent 不能因 evaluator 的来源图、不可见 parent 或私有真值获得新的内容传播权限。

运行器必须验证：

1. J1 的 `public_prior_judgment` 哈希与本组实际 J0 的脱敏结构哈希一致；
2. 每个 `content_id` 和 `evidence_card_id` 都已在该分支公开可见；
3. 根关系只能描述已经暴露的社会消息，不能凭 provenance relation 传播未暴露 parent；
4. 一次解析失败、`finish_reason=length`、超时或 HTTP 错误立即停止该新批次，不重试；
5. 真实请求必须显式确认新版本的请求数和 completion reservation 上限；
6. 输出只写脱敏案例审计和绑定收据，且输出目录不可覆盖。

离线 FakeProvider 应同时产生预设的零差异、独立来源增量、外部证据增量、顺序捷径和来源泄漏模式，确认分析器不会把它们混淆。

## 主要结果与可分析单元

首要结果不是“是否翻转”一个二元数，而是：

- `J1.ordinal_judgment - J0.ordinal_judgment`；
- `J1.confidence - J0.confidence`；
- 采纳、保留或拒绝的转移；
- 是否分享以及所分享内容是否实际可见；
- 对可见社会消息、根和 EvidenceCard 的引用。

主要比较在材料和执行前固定：

```text
自然不稳定       = self_reflection - J0
社会文本增量     = source_unshown_repetition - self_reflection
来源披露效应     = same_root_shown - source_unshown_repetition
独立性增量       = independent_roots_shown - same_root_shown
直接证据增量     = direct_evidence - self_reflection
```

每个场景 x 种子 x 初始状态组是一个配对单位，不能把来自同一个组的多个条件或同一个网络中的多个 Agent 当作独立样本。分析前还要预先定义 `eligible`：J0 已经处于方向性或行动边界、没有空间朝该条件预期方向移动的组，不用于主要方向性比较，但仍完整报告为地板/天花板诊断。

## 资格门与停止规则

进入本设计的真实行为试跑前，必须依次满足：

1. 新的来源关系结构解码资格测试通过，证明模型能按公开输入区分未显示、同根、异根和直接 EvidenceCard；这只验证结构复述，不单独证明来源会影响判断；
2. 新协议通过独立的一次性 Provider compatibility gate；
3. 新的离线状态机、解析器、脱敏审计和 FakeProvider 分析全部通过；
4. 研究者对新协议、请求上限和输出路径单独授权。

若资格门失败，只能修复来源表示、Schema 或运行器，不能分析任何不完整行为输出。若资格门通过、J0/J1 也可解析，但独立根与同根的差异接近零，则该结果应如实解释为“在所测模型和锁定协议下，没有观察到来源独立性行为增量”。它不是靠继续调提示直到出现想要方向来解决的问题。

## 从个体更新到网络

只有个体协议显示出可测的非退化输出后，才进入无干预小型网络。网络阶段仍先验证传播机制而非干预效果：同一根的多次转发只算一个根、实际曝光可回放、分享决定下一轮可见性、外部证据不能通过未暴露 provenance edge 自动流动。来源感知 Controller 最后才与无干预、普通异议和只数消息的策略比较。

因此，这个设计增加的是得到可信结果的机会和解释力，不是预设模型一定会表现出“从众”或来源效应。
