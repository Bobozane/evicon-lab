# 状态化来源依赖观点更新：离线验证 v1

## 当前状态

本文件描述的是一个新的、完全离线的协议验证器。它不是行为实验、不是网络实验、不是模型效果结论，也不授权任何网络请求。

它与已完成的 v2 因素分解开发试跑完全隔离：不读取旧输出、历史 Pilot、WVS 材料、ledger、receipt、分析结果或 evaluator-private truth，也不修改它们。

## 为什么要新增这一层

此前的开发试跑能够检查来源投影、结构化输出和脱敏审计，但不同条件是独立请求。因此，即使它们共享场景和随机种子，也不能严格称为“同一个 Agent 从初始判断更新到最终判断”。

新协议把一个逻辑单元固定为：

```text
J0：只见初始公开材料，作出一次结构化公开判断
  -> J1-self：带入实际 J0，只进行自我反思
  -> J1-unshown：带入实际 J0，见两条未显示来源的社会报告
  -> J1-same：带入实际 J0，见两条显示为同一根的社会报告
  -> J1-independent：带入实际 J0，见两条显示为两个根的社会报告
  -> J1-evidence：带入实际 J0，见一张直接 EvidenceCard
```

J0 不是完整回复或推理文字。J1 中只带入 J0 的六个允许公开审计字段：判断、公开行动、分享决定、信心、所用内容 ID 和分享内容 ID，并附带该结构的 SHA-256。每个 J1 都必须使用本组实际 J0 的相同哈希。

## 锁定的离线矩阵

- 4 个新写的、公开合成的中性场景；
- 2 个固定随机种子；
- 每个场景/种子有正序和反序两个呈现版本；
- 共 16 个逻辑组；
- 每组 1 个 J0 加 5 个 J1 分支，即每种 FakeProvider 模式 96 个逻辑请求；
- `max_tokens=256`，`temperature=0.0`；
- 全部在内存中运行，不保存 prompt、完整回复或结果文件。

三个社会消息条件在同一组中具有完全相同的两条社会文本、任务和消息顺序，唯一可见的差别是：不显示根、显示为一个根、显示为两个根。没有把“隐藏同源”和“隐藏异源”作为两个字节相同的真实调用。

直接 EvidenceCard 是单独的材料类型，不是更多社会消息，也不带“这是真的”标签。来源根只描述已可见社会消息之间的关系，不能让未暴露的上游内容进入 J1。

## 离线验证什么

FakeProvider 必须能让分析器区分三种情况：

1. 所有条件都没有差异；
2. 预设的社会重复、同源披露、独立根和 EvidenceCard 差异；
3. 输出只因消息顺序变化而变化的捷径模式。

第三种不是“来源效应”。它会被反平衡诊断标记，因此不能被混入来源独立性比较。

解析器还拒绝未知字段、重复 JSON 字段、未暴露内容 ID、判断与行动不一致、分享与内容引用不一致，以及 J0/J1 哈希不匹配。

离线命令：

```bash
.venv/bin/python -m evicon.conformity_source_behavior_update_offline_simulation_v1 --offline-smoke
```

该命令的成功只表示状态机、配对比较和安全边界在 FakeProvider 下可工作，不表示真实模型会呈现来源效应。

## 允许保存的审计面

安全审计仅含组/案例/场景/种子/条件、J0 或 J1 阶段、判断、行动、分享类别、信心、引用数量、可见根数量、证据卡数量和 prior 哈希。

它不含材料文本、根编号、prompt、完整回复、API key、headers、provider metadata 或私有真值。

## 进入真实行为试跑之前

真实模型调用仍被阻止。顺序必须是：

1. 先完成并单独审核来源关系理解的真实 24-case 资格运行；
2. 为状态化 J0/J1 协议新建独立 compatibility gate、审批和不可覆盖收据；
3. 获得研究者对新协议、请求上限和输出路径的一次性明确授权；
4. 只执行预先锁定的小规模试跑，再按预先定义的解析、地板/天花板和反平衡规则决定是否进入网络阶段。

若来源理解通过而真实 J0/J1 的独立根增量仍接近零，应如实报告为该模型和锁定协议下未观察到该行为增量。不能通过查看结果后挑场景、改提示或删除零差异条件来制造“有效果”。
