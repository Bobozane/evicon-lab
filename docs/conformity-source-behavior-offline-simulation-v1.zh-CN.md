# 来源行为因素分解：离线模拟协议 v1

更新时间：2026-08-29

## 这一步做什么

这是新研究路线的第一道开发门槛。它只检查实验设计和程序是否能把几种信息情况分开，使用预先写好的假模型回答，不调用真实模型、不联网，也不读取 API key。

它不是行为实验，不回答“模型会不会从众”，不产生论文结果，也不与旧 H-G、H-D、WVS 或既有 Pilot 合并。

## 条件矩阵

每个场景和随机种子组成一个配对组。每组包含 8 个条件：

| 条件 | Agent 看到的公开材料 | 公开来源关系 |
| --- | --- | --- |
| 独立初始判断 | 一条初始消息 | 不显示来源 |
| 自我反思 | 同一条初始消息，要求重新思考 | 不显示来源 |
| 无来源文本重复 | 初始消息和两条重复表达 | 不显示来源 |
| 同源不显示 | 同样三条消息 | 底层同源，但不显示 |
| 同源显示 | 同样三条消息 | 两条重复消息显示同一个来源根 |
| 独立不显示 | 同样三条消息 | 底层不同源，但不显示 |
| 独立显示 | 同样三条消息 | 两条重复消息显示两个来源根 |
| 外部证据 | 初始消息和直接证据卡 | 不使用社会消息来源关系 |

“同源不显示”和“独立不显示”的公开请求完全相同，只有评估器内部保留的来源关系不同。这是一个安慰剂对照，用来确认模型不能从未暴露的信息中推断来源。

## 离线规模

- 4 个作者原创的合成场景；
- 3 个固定随机种子；
- 12 个配对组；
- 每组 8 个条件，共 96 个分支；
- 两种假模型模式：预设有差异、预设无差异；
- 总计 192 次离线假请求。

每个配对组只生成一次独立初始判断。其安全摘要哈希在所有分支中复用，用来检查分支没有重新生成或互相污染初始状态。

## 检查内容

程序会检查：

- 条件、场景和种子的数量是否完整；
- 隐藏来源条件的公开文本、顺序和请求内容是否一致；
- 显示来源时，是否确实出现一个根或两个根；
- 请求中没有场景、条件、种子、内部来源关系等坐标；
- 输出只能引用实际可见的内容 ID；
- 未知字段、重复字段、格式错误和判断—行动不一致会被拒绝；
- 假模型预设的有差异和无差异模式能被配对比较恢复；
- 运行不写 `results`，不保存提示词、完整回复或私有真值。

## 运行命令

先做不渲染请求的配置预检：

```bash
.venv/bin/python -m evicon.conformity_source_behavior_offline_simulation_v1 --preflight
```

运行完整离线模拟：

```bash
.venv/bin/python -m evicon.conformity_source_behavior_offline_simulation_v1
```

两条命令都保持禁网。当前版本没有网络开关，也不会执行 12-request 或更大规模的真实行为运行。

## 通过后的下一步

这一步通过只说明“因素分解设计和分析管线可识别”。下一步应单独运行来源关系理解资格测试，确认真实模型能读懂公开的来源根数量。资格测试通过后，才进入个体层面的因素分解实验；在此之前不扩大多轮网络请求，也不测试干预效果。
